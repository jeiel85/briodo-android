# Play Store 리뷰 응답 SLA

**버전**: v1 (2026-05-12 도입)
**관련 이슈**: [#252](https://github.com/jeiel85/BrioDo/issues/252)
**목적**: Play Store 별점 평균 **4.6+** 유지, ASO/추천 알고리즘 가산점 확보

---

## 운영 원칙

| 항목 | 기준 |
|------|------|
| 응답 시한 | **24시간 이내** |
| 우선순위 | 별점 1~3점 > 별점 4~5점 |
| 응답률 목표 | **100%** (별점 1~3점), 50%+ (별점 4~5점) |
| 응답 후 액션 | 부정 리뷰에서 발견된 실제 문제 → GitHub Issue 등록 (제목 prefix: `[Review]`) |

## 응답 톤 가이드

- **존중**: "고객님" 호칭 사용. 사용자 결정/감정 비판 금지
- **사과 + 책임**: 버그는 명확히 사과, 사용자 책임으로 돌리지 않음
- **구체적 약속**: "다음 업데이트에 반영" 같은 모호한 표현보다 "v1.2 (예상 출시 X월) 반영" 형태
- **개발자 인격**: 일관된 1인칭 ("BrioDo 개발자 박용은입니다" / "BrioDo 팀입니다")
- **간결**: 응답 200자 이내 권장

## 응답 카피 템플릿

별도 디렉토리: [docs/marketing/review-templates/](marketing/review-templates/)

- [`bug.md`](marketing/review-templates/bug.md) — 버그 보고
- [`feature-request.md`](marketing/review-templates/feature-request.md) — 기능 요청
- [`misunderstanding.md`](marketing/review-templates/misunderstanding.md) — 오해/사용법 안내
- [`positive.md`](marketing/review-templates/positive.md) — 긍정 리뷰

## 운영 루틴

### 매일 (오전 9시 권장)
- [ ] Play Console 모바일 앱에서 신규 리뷰 확인
- [ ] 별점 1~3점은 즉시 응답
- [ ] 응답 작성 시 적합한 템플릿 선택 후 개인화 (사용자 닉네임, 구체적 상황 반영)

### 매주 (월요일 회고)
- [ ] 지난 주 응답률 / 응답 속도 중앙값 계산
- [ ] 응답 후 별점 상향(re-rating) 건수 확인
- [ ] 반복되는 불만 패턴 → 다음 주 개선 우선순위로 입력
- [ ] [#252 이슈](https://github.com/jeiel85/BrioDo/issues/252)에 주간 요약 코멘트 부착

## 측정 지표

| 지표 | 측정 위치 | 목표 |
|------|----------|------|
| 평균 별점 | Play Console > 평점 | **4.6+** |
| 응답률 (별점 1~3점) | 수동 카운트 | 100% |
| 응답 속도 중앙값 | 응답 시각 - 리뷰 시각 | < 12시간 |
| 응답 후 별점 상향 비율 | 수동 추적 | 30%+ |
| 1점 리뷰 비율 | Play Console | < 3% |

## 금기 사항

- ❌ 리뷰에 변명 / 사용자 책임 전가
- ❌ 다른 앱과 비교 / 비방
- ❌ 개인정보 (이메일 등) 리뷰 답변에서 요청 — DM 채널로 안내
- ❌ "곧" / "조만간" 등 모호한 약속 (시한 명시 또는 "검토 중"으로)
- ❌ 같은 사용자에게 2회 이상 답변 (편집 사용)

## 에스컬레이션

- 별점 1점이 **3건 이상** 동일 패턴으로 누적되면 → 즉시 GitHub Issue 생성, P0 후보
- 별점 평균이 **4.5 이하**로 떨어지면 → 즉시 회고 + Growth 보드 긴급 안건
